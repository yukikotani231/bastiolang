# A proved DER (ASN.1) structure checker, called from C

DER is the tag-length-value encoding under X.509 certificates and PKCS
keys. Its parsers have a long record of memory bugs, almost all from one
mistake: trusting a length field. This library checks that an input is one
well-formed DER element, recursively, and lets C walk it with spans that
are proved to lie inside the input.

| File | What it is |
| --- | --- |
| `der.bastio` | The library: `export fn der_check` and `der_read`. Proved |
| `test.c` | The C harness: vectors for each rule, the limits, a differential fuzz against an independent C checker on random and damaged DER trees, a walk with `der_read`, a benchmark |
| `run.sh` | Generates `der.c` and `der.h`, then builds and runs the harness under AddressSanitizer + UBSan (`run.sh bench`: throughput) |

```c
#include "der.h"   /* generated by bastioc0 --header */

bst_e_Der d = der_check(s, len);        /* Ok(element count) or Bad(offset) */

/* Walk it: every span is inside s[0..len). */
bst_e_Tlv t = der_read(s, len, at);
if (t.tag == bst_e_Tlv_Ok) {
    use(t.u.Ok.tag, s + t.u.Ok.value, t.u.Ok.end - t.u.Ok.value);
    at = t.u.Ok.end;                    /* the next sibling */
}
```

The rules (strict DER, for what the checker supports):
- a tag is one byte below 31 in its low five bits (the high-tag-number form
  is rejected);
- a length is definite: one byte below 128, or `0x81`..`0x84` followed by
  that many bytes, with no leading zero and a value of at least 128 (the
  shortest form);
- a value lies inside its container, and the value of a constructed
  element (tag bit `0x20`) is a list of elements that fills it exactly;
- at most 64 constructed elements nest inside each other (deeper input is
  rejected rather than recursed into);
- the input is one element, with nothing after it.

What it does not check: the meaning of the elements (that an INTEGER is
minimal, that a SET is sorted, which tags a certificate needs). It checks
the structure that every one of those rests on.

## What is proved

For every input, with no runtime check in the generated C:
- no read outside `s[0..len)`, and no overflow, including in the length
  arithmetic: a 4-byte length is at most 2^32 - 1, and the loop invariants
  that bound it are checked;
- every span `der_read` returns satisfies `at < value <= end <= len`, and
  `der_check`'s error offsets are inside the input;
- an element count is at most `len`.

A bug in the length code is a compile error. Admitting five length bytes
(`b > 133` instead of `b > 132`) is rejected with `E-VERIFY-OVERFLOW` and a
counterexample, before any test runs.

**Not proved:** that the checker accepts exactly the DER it should. `test.c`
compares every verdict, error offset and element count with an independent
C checker (pointers rather than offsets, shifts rather than
multiplication), on hand-written vectors, on the limits (a long-form length
of 127 and of 128, 63 to 66 nested SEQUENCEs) and on random trees that are
then damaged: a byte changed, a header bit flipped, the end cut off, or a
byte added. Weakening the minimal-length rule or the depth limit by one
makes it fail.

## Speed

`bench/der` checks a 16 MiB SEQUENCE of small nested records against a C
twin with the same code (`bench/run.sh der`): on one x86-64 Linux machine
(2026-10-10), 0.75 to 0.77 times the time of the C. The two differ only in
how the C compiler happened to inline them, so read it as parity.
`run.sh bench` compares `der_check` with the reference checker in `test.c`
(a different algorithm) on 64 MiB of random trees: about 1610 MiB/s against
1850 MiB/s on the same machine.
