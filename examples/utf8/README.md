# A proved UTF-8 validator and decoder, called from C

Strict UTF-8 (RFC 3629, Unicode table 3-7) as a C library written in
Bastio. Validating text from outside is a classic place for an
out-of-bounds read: a decoder looks ahead for continuation bytes that may
not be there.

| File | What it is |
| --- | --- |
| `utf8.bastio` | The library: `export fn utf8_validate` and `utf8_decode_into`. Proved |
| `test.c` | The C harness: boundary vectors, a differential fuzz against an independent C decoder, a benchmark |
| `run.sh` | Generates `utf8.c` and `utf8.h`, then builds and runs the harness under AddressSanitizer + UBSan (`run.sh bench`: throughput) |

```c
#include "utf8.h"   /* generated by bastioc0 --header */

bst_e_Utf8 v = utf8_validate(s, len);
if (v.tag == bst_e_Utf8_Valid) {
    /* v.u.Valid code points */
} else {
    /* the ill-formed sequence starts at v.u.Invalid */
}

/* Decode into a buffer you own, 4 bytes (UTF-32LE) per code point: */
bst_e_Decoded32 d = utf8_decode_into(s, len, out, out_len);
```

## What is proved

For every input, with no runtime check in the generated C:
- no read outside `s[0..len)` and no write outside `out[0..out_len)`;
- no overflow; every byte written is `<= 255`;
- `utf8_decode_into` never frees or replaces `out` (it is the caller's);
- the `ensures` clauses: a valid input has at most `len` code points, an
  error offset is inside the input, `Ok(c)` fits in `out` (`4c <= out_len`)
  and `TooSmall(need)` is larger than `out_len`.

**Not proved:** that exactly the well-formed sequences are accepted, and
that the code points are decoded correctly. `test.c` checks both against a
decoder written the other way round (decode by the lead byte's length, then
reject overlong forms, surrogates and values past U+10FFFF), on vectors at
every boundary of table 3-7 and on random, mostly near-valid input. The
harness does catch a wrong range: widening the `ED` row to admit surrogates,
or the `F4` row by one value, fails it.

`utf8_decode_into` validates the whole input before it writes anything, then
decodes in a second pass. The prover does not know that the second pass sees
the sequences the first one accepted, so the second loop still tests for an
ill-formed sequence and for room in `out`. These are ordinary branches in
the source, not checks the compiler added, and they never fire.

## Speed

`bench/utf8` compares the generated code with a C twin that has the same
algorithm (`bench/run.sh utf8`): on one x86-64 Linux machine (2026-10-10),
1.02 to 1.04 times the time of the C. `run.sh bench` compares
`utf8_validate` with the reference decoder in `test.c` on 64 MiB of mixed
text: about 375 MiB/s against 345 MiB/s on the same machine.
