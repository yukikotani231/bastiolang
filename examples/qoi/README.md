# A proved QOI image codec, called from C

[QOI](https://qoiformat.org/) is a small lossless image format: a 14-byte
header, a stream of one- to five-byte chunks, and an end marker. Image
decoders are a classic place for memory bugs, because a hostile file
controls both how much memory the decoder asks for and where it writes.
This library decodes and encodes QOI, and is proved never to write outside
a buffer, whatever the input. Unlike the other examples it allocates large
buffers, so it also shows how a Bastio library reports running out of memory
to C instead of aborting.

| File | What it is |
| --- | --- |
| `qoi.bastio` | The codec: a strict decoder and an encoder that writes what the reference encoder writes. Proved |
| `lib.bastio` | The C API: `export fn qoi_decode`, `qoi_encode` and `qoi_encode_into`. Proved |
| `test.c` | The C harness: round trips compared byte for byte with an encoder written in C, a differential fuzz against an independent strict C decoder, out-of-memory tests, a benchmark |
| `run.sh` | Generates `qoi.c` and `qoi.h` from `lib.bastio`, builds the harness and runs it under AddressSanitizer + UBSan (`run.sh bench`: throughput) |

## The C API

```c
#include "qoi.h"   /* generated by bastioc0 --header */

/* Never more than 2^24 pixels from this caller: a hostile header cannot
 * make it allocate more than 64 MiB. */
bst_e_QoiDecoded d = qoi_decode(file, file_len, 1 << 24);
switch (d.tag) {
case bst_e_QoiDecoded_Ok:          /* d.u.Ok.width, .height, .channels, .colorspace */
    show(d.u.Ok.pixels.data, d.u.Ok.pixels.len);
    free(d.u.Ok.pixels.data);
    break;
case bst_e_QoiDecoded_Err:         /* d.u.Err: offset of the first bad byte */
case bst_e_QoiDecoded_TooBig:      /* over the caller's limit, or 400 million pixels */
case bst_e_QoiDecoded_OutOfMemory: /* malloc failed; nothing leaked */
    break;
}

bst_e_QoiEncoded e = qoi_encode(pixels, w * h * 4, w, h, 4, 0);
if (e.tag == bst_e_QoiEncoded_Ok) {
    write_file(e.u.Ok.data, e.u.Ok.len);
    free(e.u.Ok.data);
}
```

`qoi_encode_into` writes into a buffer the caller provides and returns the
length written. It needs room for the longest possible encoding,
`w * h * (channels + 1) + 22` bytes, and otherwise returns `TooSmall` with
that size and writes nothing. It allocates only the 256-byte table of
recently seen colors.

## What is proved

For every input, with no runtime check in the generated C:
- no read or write outside a buffer, including the 64-entry color table
  and the output, whose size is computed from a header the attacker
  controls;
- no integer overflow, underflow or division by zero;
- every byte written is `<= 255`;
- no leak and no double free, on every path, including every error and
  every allocation failure;
- the shapes in the `ensures` clauses: a decoded image has 3 or 4
  channels, at most `max_pixels` pixels, and exactly
  `width * height * channels` bytes of pixels; an error offset is inside
  the input; `qoi_encode_into` returns a length inside `out`.

Allocation is `try_balloc`, which returns an empty buffer when memory runs
out, and the prover checks that the length is tested before any byte is
used. Leave out the test after the decoder's two allocations, and the
compiler rejects it:

```
qoi.bastio:123:34: error[E-VERIFY-INVARIANT]: could not prove the loop invariant `(blen(out) == total) && (blen(seen) == 256)` on entry to the loop
```

(and without that invariant, the first read of the color table fails with
`E-VERIFY-BOUNDS`). So `OutOfMemory` is a result the caller sees, never a
crash. `test.c` checks this by capping AddressSanitizer's allocations at
64 MiB and decoding a header that asks for 400 MB.

**Not proved:** that decoding inverts encoding, or that the encoder
writes what the reference encoder writes. That is functional correctness,
which is opt-in in Bastio and not attempted here. `test.c` checks both by
testing: every encoding is compared byte for byte with an encoder written in
C the way the reference `qoi.h` writes it (signed differences, a union
compare of pixels), and every decoding (verdict, error offset and pixels)
with an independent strict decoder, on round trips and on mutated,
truncated and extended inputs.

## Strictness

The decoder accepts exactly what a well-behaved encoder writes, and points at
the first byte that is wrong:
- the magic `qoif`, a width and height above 0, 3 or 4 channels, and a
  colorspace of 0 or 1;
- chunks that decode exactly `width * height` pixels: data that runs out
  early, a run past the last pixel, or chunks after it are errors (the
  reference decoder fills or ignores them instead);
- then the end marker, seven 0 bytes and a 1, and nothing after it.

## Speed

`run.sh bench` encodes and decodes a 4096 by 4096 RGBA image (64 MiB of
pixels, with runs, small steps and repeated colors) and compares with the C
encoder and decoder in `test.c`, built with the same `-O2`. On one x86-64
Linux machine (2026-10-10), decoding ran at about 370 to 420 MiB/s in Bastio
and 390 to 440 MiB/s in C, and encoding (`qoi_encode_into`, into a
buffer like the C encoder) at about 290 MiB/s in Bastio and 390 to 460 MiB/s
in C. The encoder compares pixels a byte at a time where the C encoder
compares them as one 32-bit word; Bastio has no way to say that yet. The
proofs themselves leave no checks behind. Numbers vary by machine; run it.
